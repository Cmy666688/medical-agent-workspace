# 本机与公网共享账号、家庭和对话

## 当前行为

- 本机 `localhost:8502` 与公网 HTTPS 入口读取同一套 `runtime/shared` 用户数据库。
- 同一用户名和原密码可在两边登录，管理员 `123`（称呼 `cmy`）也能在公网登录并进入用户管理。
- 本机创建的家庭和原邀请码可由公网账号加入；成员授权仍由本人决定，加入家庭不会自动开放私有健康记录。
- 对话、核对卡、账号角色、登录撤销和调用配额共用，记录仍按不可变身份 ID 验证归属。
- 参考库索引、模型缓存、服务日志与 Cookie 配置继续按服务保存，原始用户数据库和迁移备份不上传 GitHub。

四个已有家庭分别保留，成员通过对应邀请码加入目标家庭。刷新邀请码会让旧码失效；邀请卡现在校验当前家庭和最新摘要，避免显示其他家庭或已被刷新的邀请码。

## 本次重名处理

本机原 `abc` 保留。原公网 `abc` 按用户确认改为 `abc_public`，原密码仍有效；身份 ID、家庭、历史对话和权限不合并到本机 `abc`。

## 源码

| 文件 | 作用 |
| --- | --- |
| `agents/storage_paths.py` | 账号、家庭、对话和监控用量的统一路径解析；独立测试目录不读取生产共享库 |
| `merge_user_data.py` | 只读预检、SQLite backup 快照、显式重名映射、逐条冲突检查、完整性校验和最后激活 |
| `agents/family.py` | 同一个共享库验证邀请码；加入事务去重；保留家庭共享权限检查 |
| `family_invite_ui.py` | 邀请信息与当前家庭绑定；过滤过期、刷新前或其他家庭的缓存邀请码 |
| `reminder_worker.py` | 共享库单实例文件锁；另一服务的进程待命，避免重复调度 |
| `reload_public.ps1` | 验证并停止旧 Web/提醒进程及其子进程，保留原隧道连接 |
| `test_shared_user_store.py` | 不同账号迁移、原密码、管理员、公网加入、旧令牌、权限和缓存邀请验证 |

## 迁移方式

先停止本机和公网 Web 服务及提醒进程，防止备份与切换期间出现新写入。可保留 cloudflared 隧道进程，切换服务后继续使用原网址。

```powershell
# 只检查，不修改或激活
.venv\Scripts\python.exe merge_user_data.py
# 两边服务和提醒进程已停止后，使用明确确认的重名映射执行
.venv\Scripts\python.exe merge_user_data.py --apply --rename-public abc=abc_public
```

`--apply` 在新的 staging 目录生成结果，不覆盖原目录。每个源数据库通过 SQLite backup API 生成快照，备份位于 `runtime/backups/user_merge_*`。遇到未解决的唯一键或不同内容共用 ID 时中止；不会用 `INSERT OR IGNORE` 丢弃冲突用户。校验通过后才发布 `runtime/shared` 并原子写入私有 `config/storage.local.toml`。

本次迁移后应恢复两个 Web 服务和提醒进程。运行日志仍在原 `runtime`、`runtime/public`；迁移清单在共享目录和备份目录各有一份，不包含密码原文、令牌或问诊正文。

## 回退边界

原 `runtime/family.sqlite`、`runtime/conversations.sqlite`、`runtime/monitor.sqlite` 及 `runtime/public/` 下原数据库均保留。若刚切换即发现问题，应先停止写入，备份共享库，再由管理员处理配置回退。共享库启用后的新增记录不能直接丢弃；不能只删配置就宣称数据已完整回退。
