# 计价与微调评估核对

## 为什么有调用却显示未计价

原配置输入/输出单价都是 0，程序把默认的 0 理解为尚未配置价格，而不是免费。检查时 85 条成功日志均未保存成本，其中 12 条缺少 token 用量。历史记录还含不同模型和调试记录，不能把全部记录都按当前供应商单价计算。

新版监控分别显示：已记录估算、历史按当前主模型单价参考估算、缺少 token 用量、缺少适用单价。历史参考值只在界面计算，不改写原始日志；缺失用量不补成零，也不用预算预留值冒充供应商实测 token。不同币种分开汇总。

当前费用汇总基于可计量的成功调用，失败、取消和网络异常请求仍可能存在未完整记录的计费；不把这个合计作为完整账单。

## 当前 DeepSeek 参考口径

核对日期：2026-11-02。来源：[DeepSeek 官方模型与价格](https://api-docs.deepseek.com/quick_start/pricing/)。

当前配置的 `deepseek-flash` 使用 **USD、峰时、输入全部未命中缓存** 的保守参考单价：每百万输入 token 0.30 美元，每百万输出 token 1.20 美元。它仅用于估算，没有修改 API 密钥、模型、实际供应商扣费或 token 预算。

供应商还有缓存和非峰时折扣，且可调整价格，因此这些参考数值不能称作实际账单。备用模型未配置对应单价时继续显示未知；不同历史模型不套用 Flash 单价。管理员可在“评估与设置 → 模型接口”调整当前会话的单价、币种和估算口径；服务默认价格仍由私有配置文件维护。

源码：`agents/costs.py` 做分类和参考计算，`agents/llm.py` 保存调用时的单价/币种/口径元数据，`app_pages/monitor.py` 展示。测试见 `test_cost_evaluation_ui.py`。

## 为什么单例变差但整体指标提高

同一组 24 条留出问题的纯向量检索指标：

| 指标 | 微调前 | 微调后 |
| --- | --- | --- |
| Recall@1 | 29.17% | 50.00% |
| Recall@5 | 58.33% | 83.33% |
| Recall@10 | 83.33% | 91.67% |

原界面固定展示的鼻炎资料示例确实从第 2 名降到第 3 名；这条退步没有被替换或隐藏。重新使用既有向量集合、同一套原始问题/标签和各自模型编码进行逐题核对后：**12 条提升，3 条退步，9 条持平**，重算的三个总体指标与原保存结果一致。

训练使用了 72 条非弱标签训练问句，运行 50 步。小规模训练和相近疾病区分可能造成局部退步，但没有消融实验就不能把某个原因当作已证明结论。训练 loss 降低也不保证每条检索问题的排名都提高。

新版评估页明确标注 Recall 越大越好、排名越小越好；保留单例退步提示，展示全部 24 条的前后排名并支持按退步/提升/持平查看和下载。相似度分数不是疾病概率，不同模型的分数也不是同一把校准尺。

本次没有重新训练、改标签或替换已发布模型，原 `evaluation.json` 保留。逐题审计保存在本机忽略提交的 `runs/check_full_1031/audit_comparison.json`。后续训练脚本也会保存完整逐题结果，便于检查退步而非只展示一个案例。

源码：`audit_retrieval_evaluation.py` 重算审计，`retrieval_evaluation_ui.py` 展示，`medical_retrieval.py` 保存新训练的逐题结果。线上 BGE/BM25/RRF 和可选 LLM 重排属于另一条检索流水线，不把其成绩冒充纯向量微调对比。
