# 用药资料接入

已在独立用药 Agent、完整问诊协作和风险页的用药核对中接入本地只读索引。无需额外 API 密钥即可查询；不会把药名发送到第三方服务进行匹配。完整问诊中可选的在线用药复核仍使用用户已配置的模型，并只能引用命中的药品证据，不能拿疾病百科代替药品说明书。

## 当前数据

- TFDA：原始 72,096 行，按许可证去重后 66,527 个许可证。重复记录来自登记信息，核查过重复许可证的药名、成分、注销状态和有效期一致。保留地区、剂型、成分原文、有效期、注销状态和说明书/包装链接。
- openFDA：15 条标签样本。只按完整成分组合匹配，不能把单方说明书替代复方说明书。输出原文摘录与版本链接，明确这是美国同成分标签参考，不是所选 TFDA 产品的说明书。
- DDInter：A 类相关子集 56,367 条。返回已有药物对及原始等级；Unknown 或未命中不等于安全。CSV 没有的机制、处置建议不会自动补造。

来源与许可见[调研报告](医学数据集调研与接入建议.md)。TFDA 为政府资料开放授权条款第 1 版；openFDA 的 CC0 原则含第三方内容例外；DDInter 为 CC BY-NC-SA 4.0。当前用于非商业课程研究；商业部署需要另行处理相应授权。

## 构建

```powershell
.\.venv\Scripts\python.exe -m pip install opencc-python-reimplemented==0.1.7
# 尚未下载时执行，下载器同时获取调研所需的其他数据：
.\.venv\Scripts\python.exe fetch_medical_datasets.py
.\.venv\Scripts\python.exe -m agents.drug_data
```

构建器校验 manifest 中的来源 SHA-256，离线处理后写入 `data/medication/knowledge.sqlite`；完整性检查通过后原子替换。首次构建可能需要数分钟，不在网页请求中构建。索引和原始数据均不上传到 GitHub。可用 `MEDICAL_DRUG_DB` 指定其他索引文件。

本机与公网实例共享只读药品资料，账号、家庭和历史记录仍分别存储。源文件或依赖更新后重建索引，并刷新应用进程。公网可执行 `reload_public.ps1`：仅重载已核验的公网应用/管理进程，复用现有隧道和提醒进程，保持当前 HTTPS 地址。完整关机或重建隧道仍会改变临时地址。

## 匹配边界

1. 每行一种准确药名，最多 8 种。支持简繁体、英文、精确商品名及许可证号；有限的明确通用名/盐型术语映射不代表全量中文药名标准化。
2. 模糊检索只提供候选许可证，不自动确定成分；同名但成分不同的产品必须进一步选择。带剂量的自由描述不猜测药品。
3. 通用名候选可能包含复方，但计算时只使用用户明确给出的成分；选择完整复方商品名或许可证后才展开其实际成分。保留 topical/systemic 等限定，避免不同制剂被错误合并。
4. 重复成分提示只要求核实实际重复用药，不指导停药；过敏与交叉过敏尚未自动完成审查。
5. 未提供药名、未识别、资料缺失、未覆盖、等级未知均分别显示。数据规模不等于临床有效性或全面安全审查。

## 验证

`python -m unittest test_medication_knowledge` 使用明确的合成夹具检查：来源回查、简繁体、复方、歧义、未知、重复、历史许可、精确匹配、SQL 参数化、损坏来源不覆盖现有索引及可读页面。

本次还验证了真实索引中的检索路径，并经公网正常注册、进入用药页面和提交表单，确认 TFDA 数量、openFDA 摘录及 DDInter 匹配记录实际显示。测试只证明软件链路，不构成医学效果验证。
