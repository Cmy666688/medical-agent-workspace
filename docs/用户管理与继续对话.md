# 用户管理与继续对话

## 如何继续已有问诊

1. 登录自己的账号，进入「工作台 → 历史对话」。
2. 找到要接着说的记录，点击「继续对话」。
3. 在问诊页输入新消息；系统恢复该对话的近期 LangChain 消息、个人情况和信息核对卡。
4. 重新登录时优先恢复该账号最后选中的对话；新建对话仍会保留旧记录。

问诊页和协调器显示当前对话名称、账号及已保存轮数。累计预留额度不足时，可点击「保留上下文开启续聊」：把当前对话、个人情况及核对卡保存为一个独立续聊快照，并恢复近期历史。原记录不修改，续聊使用新会话配额；账号的公网当日总额度继续累计。基础历史恢复和快照复制不调用模型 API。

这不是无限上下文：SQLite 保留完整记录，模型近期历史按现有逻辑保留最近六轮；本地提取复用最近三条用户描述。更早信息可以通过核对卡和用户重新补充进入当前上下文。

## 用户管理入口

管理员登录后可见「用户与权限 → 用户管理」（`/users`）。普通账号访问同一路径只看到权限说明，不能调用管理接口。

- 搜索注册用户、查看称呼、角色、启用状态及有效登录会话数。
- 创建普通账号，私下交付初始密码及一次性提供的恢复码。
- 修改称呼、角色、启用状态；停用或角色变化会撤销该用户的现有登录会话。
- 撤销指定账号的全部登录会话。
- 查看管理操作审计，不包含密码、令牌或问诊正文。
- 管理员不能停用自己或移除自己的管理员权限。
- 不提供永久删除用户或替用户读取私有问诊的管理操作。

用户可在「我的账户」修改自己的称呼、密码及退出登录。

管理员必须由机器管理者在本机显式配置；注册不会自动成为管理员。配置命令：

```powershell
# 在项目根目录执行；该用户名必须已经在对应服务注册。
.venv\Scripts\python.exe manage_users.py 123 --runtime-profile local
# 如以后需要公网管理员，另行明确选择公网账号：
.venv\Scripts\python.exe manage_users.py USERNAME --runtime-profile public
```

本次按用户要求，已给本机称呼为 `cmy` 的原有账号授予管理员权限。核对数据库后，其登录用户名为 `123`，没有另外创建 `cmy` 空账号，也没有修改其密码。公网与本机仍使用两个独立运行目录，账号与权限不会自动同步。

## 数据隔离如何实现

| 数据 | 隔离方式 |
| --- | --- |
| 账号 | 不可变身份 ID；密码 PBKDF2 加盐摘要；登录令牌仅存摘要并有有效期 |
| 对话和核对卡 | 每次读写通过登录令牌解析身份，按 `conversation.owner` 验证；管理员也不能绕过归属 |
| 最近活动 | 数据库查询按已验证身份筛选，不再向普通本机用户展示全站活动 |
| 当前对话偏好 | `conversation_preferences.owner` 每个身份单独保存；不能选中别人的对话 |
| 内存状态 | 切换账号后清理近期历史、视觉结果、Agent 输出和字段表单；恢复内容必须重新经过归属校验 |
| 家庭数据 | 保留既有家庭成员归属与本人授权，停用账号不能继续访问 |
| 运行管理 | 本机管理员访问监控和配置；普通用户不进入；公网服务保留其既有管理限制 |
| 共享知识库 | 通用参考资料供用户检索，增量资料维护限制为本机管理员，不用于存放私有病历 |

客户端传来的用户名或对话 ID 不能决定数据归属。账号权限由服务端 SQLite 查询决定，SQL 参数使用绑定值。注册后的用户名和身份 ID 不因称呼修改而变化。

## 代码入口与讲解分工

| 路径 | 核心内容 | 讲解归属 |
| --- | --- | --- |
| `agents/user_management.py` | 管理接口鉴权、角色/状态变更、会话撤销及审计 | 数据工程师 |
| `agents/accounts.py`、`agents/family.py` | 登录、密码、角色、启停校验与家庭权限衔接 | 数据工程师 |
| `agents/conversations.py` | 按 owner 鉴权、当前对话偏好、续聊快照 | 数据工程师 |
| `conversation_ui.py` | 切换账号清理内存、重建 LangChain 历史、续聊按钮 | 数据工程师讲恢复机制，Web 工程师讲交互 |
| `app_pages/users.py`、`auth_ui.py`、`app.py` | 用户管理表单、账户入口及权限导航 | Web 工程师 |
| `agents/telemetry.py`、`app_pages/home.py` | 最近活动按当前用户查询 | 数据工程师负责过滤，Web 工程师负责展示 |
| `manage_users.py` | 本机命令设置初始管理员，不作为 Web 接口 | 运行维护 |
| `test_user_management.py` | 合成账号的权限、停用、恢复、续聊和隔离测试 | 联合验收 |

LLM 岗位继续消费恢复后的近期历史，不实现账号权限；算法岗位继续维护共享参考资料的检索，不维护用户数据。
