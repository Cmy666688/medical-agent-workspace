## 5. 尚不能判定全部完成的具体原因

### A. 当前检索成绩与旧结果口径不同

本轮使用当前 `RetrievalService.search` 的 BGE + BM25 + RRF 路径，24 条固定 eval 问句、K=10、threshold=0，仅主疾病库，不调用生成模型：

| 指标 | 本轮当前混合检索 | 页面文件内历史向量微调后结果 |
| --- | --- | --- |
| Recall@1 | 8/24 = 33.33% | 50.00% |
| Recall@5 | 16/24 = 66.67% | 83.33% |
| Recall@10 | 17/24 = 70.83% | 91.67% |

原始结果保存在本地 `runtime/course_audit_retrieval.json`。两列的检索流程不同，不应直接把旧表当作当前在线混合检索的性能证明。需要统一标明方法、参数和版本，排查混排效果；截图未规定数值达标线，因此这是效果与验收证据缺项，不是“没有写评估功能”。

### B. 成本功能已写，但实际成本未生效且覆盖不完整

当前文件配置中的主、备、视觉六个单价均为 0；本机已记录的 26 次成功 LLM 调用均未计价。因此不能声称已经显示了实际金额。填入供应商价格后，成功且返回 token 用量的调用可按请求、用户和日期汇总。

此外，当前金额汇总基于成功的 `kind=llm` 事件。失败尝试即使供应商产生费用，也未完整计入统一金额；不能把“已计价成本”当作完整账单。

### C. 公网没有管理者可访问的监控/评估入口

本机 `http://localhost:8502/monitor`、`/evaluation` 登录后可使用。公网启用 `MEDICAL_PUBLIC_MODE`，`app.py` 隐藏“项目管理”，对应路由只显示管理说明；公网还使用独立监控数据库，本机面板不会自动汇总公网事件。

若课程验收要求老师直接在公网查看监控，应补充受权限保护的管理员入口及公网指标视图，不能简单向所有普通成员开放全站记录。

### D. 调用前拦截需要统一失败埋点

本轮在隔离目录复现：直接调用共享客户端、设置 `budget_tokens=1`，正确抛出 `budget_overflow`，没有发出 HTTP 请求，但 `failure` 事件为 0。原因是预检和 `reserve` 位于统一网络异常记录逻辑之外；部分调用方能补记，部分独立页只保留局部错误结果。

证据：`runtime/course_audit_budget_logging.json`。需要在统一客户端记录这些拒绝原因，并避免调用方重复统计同一次失败。
